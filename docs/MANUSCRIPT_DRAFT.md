# EAGLE: Evidence-Aligned Groundwater Level Explorer for Auditable Florida USGS Groundwater Trend Analysis

**Draft status.** This manuscript draft reflects the repository closeout state on 2026-04-16. The user-facing system name is EAGLE (Evidence-Aligned Groundwater Level Explorer); repository paths and environment variables may still contain the historical `GroundwaterGPT` name for compatibility.

## 1. Introduction

Public environmental monitoring programs have created large scientific datasets whose practical value is limited by the gap between available records and usable research outputs. The U.S. Geological Survey (USGS) National Water Information System is a central example for groundwater science: it exposes long-running well records, but answering a local research question still requires site discovery, data cleaning, time-series aggregation, hydrogeologic context, visualization, and careful citation of the source records. Recent language-model systems make scientific data easier to query, but many rely on retrieved text as the primary evidence layer. For hydrologic applications, that is not enough. A useful system must keep quantitative claims tied to measured records, make charts reproducible, and expose the data and method path behind each answer.

This study presents EAGLE, an auditable research interface for Florida groundwater monitoring records. The central contribution is not the use of a language model by itself. The novelty is a deterministic USGS data pipeline that transforms local Florida well records into claim-bound, chart-backed, cross-cohort groundwater summaries, then exposes those summaries to a language model only through structured claim and evidence identifiers. In this design, the language model functions as an evidence-guided synthesis layer for explanation and next-step guidance. Numeric conclusions, trend directions, cohort comparisons, source links, chart payloads, citation-integrity metrics, and provenance hashes are produced by deterministic code before any free-form explanation is emitted.

The manuscript focuses on a bounded Florida monitoring network rather than a national deployment. The repository currently contains 44 site metadata entries and 40 canonical local USGS time-series CSVs, with daily depth-to-water observations spanning 1994-01-01 through 2026-04-05 across the shipped dataset. EAGLE uses these records to answer descriptive trend and aquifer-context questions, including site-specific change, nearest-well location summaries, cross-well cohort behavior, cross-aquifer comparisons, divergent-well screening, map context, and reproducible time-series chart generation. The objectives are to describe the architecture, evaluate whether the deterministic layer returns citation-complete and reproducible answers, and identify the statistical limitations that must be addressed before the system can support stronger hydrogeologic inference.

## 2. Methods

EAGLE is implemented as a FastAPI backend with a React frontend. The backend prioritizes deterministic analysis before any language-model synthesis. A routing chain detects explicit well IDs or names, aquifer names, Florida locations, multi-location comparisons, and network-wide questions. Location queries use a reproducible nearest-neighbor proxy-selection rule based on Haversine distance with a county-match bonus. This rule is a site-selection heuristic rather than a spatial interpolator.

The data layer operates on canonical USGS CSV files named `usgs_<site_id>.csv`, each containing `site_no`, `datetime`, and `value`, where `value` is depth to water in feet below land surface. The loader coerces timestamps and numeric values, drops invalid rows, sorts chronologically, and caches the resulting per-site dataframe. Downstream analysis resamples daily values to month-start means. For each well, the deterministic pipeline computes record start and end dates, net change, ordinary least-squares annualized rate of change on monthly means, and a qualitative trend class.

The cohort layer is where much of the manuscript novelty sits. For a selected set of wells, the system computes a cross-well trend distribution, mean annual change, standard deviation of annual change, top divergent pairs, candidate changepoints, deterministic behavior clusters, and a cohort risk label. Divergent pairs identify wells with the most contrasting annual rates and are used as screening signals for local heterogeneity or possible measurement/context differences. Candidate changepoints are detected by comparing a single OLS fit with a two-segment OLS fit and requiring at least a 20% residual-error improvement. Behavior clusters are built from standardized local-data features, including annual change, seasonal amplitude, and confinement indicator. These cohort tools are reproducible screening heuristics, not formal proofs of aquifer connectivity, causality, or regime shift.

For presentation, the same deterministic object is rendered into both human-readable text and machine-readable audit fields. Each report includes `claim_citations`, claim verdicts, citation summary, section confidence, citation-integrity status, and a `structured_response` using the `evidence_response_v1` schema. Every quantitative claim in the deterministic report binds to registered claim IDs and evidence IDs. For structured LLM synthesis paths, model claims must intersect with the pre-approved deterministic registry; claims without valid IDs are dropped. This claim/evidence binding is the core guardrail that prevents the language model from becoming the source of quantitative groundwater conclusions.

The chart pathway is similarly constrained. Time-series chart payloads are produced as Recharts-ready JSON by a single chart builder used by deterministic and agentic paths. Charts include monthly well series, a cohort-average series when applicable, trend overlays with annualized rates, highlighted divergent wells, and chart insight bullets. Chart follow-ups are organized as grounded interpretation rather than raw data restatement. The interpreter classifies each chart question into one of five deterministic intents — shallow-vs-deep comparison, fastest-changing well, cohort average meaning, risk explanation, or general — using regex matching against the question text. Each intent has a dedicated answer builder that constructs the response directly from the chart's EvidencePack (the cross-well metrics, per-site rates, and site metadata already computed by the deterministic layer). A shallow/deep question groups wells by confined vs unconfined using site metadata, computes mean rates for each group, and leads with a direct comparison ("the N shallow wells average X ft/yr while the M confined wells average Y ft/yr") plus the largest well-level rate gap and seasonal amplitude when available. A fastest-changing question sorts per-site metrics by annual rate and names the well. The visible answer is composed as: direct answer, up to two supporting evidence sentences, and one caveat. The deeper analytical material — observed signal, hydrogeologic meaning, possible explanations, evidence needed, management implication, confidence note — remains in structured fields for the frontend Analytical Depth panel and audit trail. When the interpreter returns aquifer-type comparison groups, the panel renders a shallow-vs-deep row with group means, seasonal amplitude, and the largest well-level gap. Key observations prefer answer-relevant observations derived from the detected intent, so the panel follows the question rather than repeating generic chart boilerplate.

Because the measured variable is depth to water below land surface, the frontend inverts the y-axis so deeper water levels plot downward. Map context is generated from the same site metadata used by the router, allowing users to inspect the spatial distribution of the selected Florida wells without leaving the application.

Reproducibility is tracked through a `research_provenance_v1` block. Each response records a code commit when available, a SHA-256 hash of the response, hashes of the data snapshot and configuration files, and method flags describing the trend, changepoint, cluster, citation, and external-covariate settings. This means a reviewer can inspect not only a natural-language answer but also the data files, chart payload, claims, citations, and method path behind it.

## 3. Results and Discussion

### 3.1 Deterministic Benchmark Performance

The manuscript-facing benchmark contains 68 groundwater questions across routing modes including generic fallback, site fallback, aquifer fallback, and network fallback. In deterministic fallback mode, with the language-model agent disabled, EAGLE passed 68 of 68 cases. The current benchmark report produced an overall score of 1.000, average citation coverage of 1.000, average claim-citation coverage of 1.000, average section-citation coverage of 1.000, and average claim-verdict coverage of 1.000. Median response latency was 1.554 s and maximum latency was 3.247 s on the latest clean local run. These latency values were measured with the FastAPI in-process `TestClient`; deployed client-server latency will be higher and should be benchmarked separately.

These results should be interpreted as a software and auditability evaluation, not as proof that the hydrologic trend labels are scientifically optimal. The benchmark verifies that the system returns expected fields, cites claims, reports dates and trend metrics, emits structured evidence, and satisfies response-time thresholds. It does not validate risk-label calibration, groundwater causality, seasonality-corrected trends, or external generalization.

### 3.2 USGS Data Presentation and Cross-Cohort Analysis

The strongest result is the integration of raw USGS well records into a usable research presentation layer. A user can ask about a Florida location or aquifer and receive a cohort summary that includes the wells selected, their aquifer labels, period of record, net changes, annualized rates, cross-well trend distribution, highlighted divergent pairs, candidate changepoints, behavior clusters, and source URLs. This turns a collection of individual site records into an auditable cross-cohort view that can support exploratory groundwater research and manuscript drafting.

The cross-cohort design is important because single-well trends can be misleading when interpreted without nearby wells, aquifer context, or record-length visibility. EAGLE does not claim that a divergent pair proves a hydrologic mechanism. Instead, it makes divergence visible, ties the observation to specific site records, and encourages follow-up review. That is an appropriate role for an auditable screening interface.

### 3.3 Chart and Map Outputs

The chart layer makes the deterministic analysis inspectable. Time-series payloads expose monthly depth-to-water values, cohort-average behavior, highlighted wells, and trend overlays using the same annual rates reported in the text and claim registry. A cross-path parity test ensures that deterministic, agent-attached, and streaming paths share the same chart schema. This avoids a common failure mode in AI-assisted analysis systems where text and visuals are generated by separate logic and can drift apart.

Map outputs provide geographic context for the monitored wells and for location-based cohort selection. The current nearest-neighbor method is intentionally simple and reproducible. It should be described as a proxy-selection method for monitored wells near a user-referenced place, not as interpolation, regional modeling, or a complete spatial analysis of Florida groundwater.

### 3.4 Language-Model Role and Evaluation Status

The codebase contains two LLM entry points, but only the deterministic layer and the intent-aware chart interpreter are evaluated.

AI is used as an interpretation and communication layer, not as the source of measured facts. The operational pipeline is: user question → deterministic router/site selector → USGS CSV and metadata analysis → chart, numeric claims, citations, and provenance → deterministic interpretation brief → evidence-guided synthesis for `next_goal` and grouped follow-up questions → optional narration/synthesis → frontend answer and Analytical Depth panel. In the current/default demo configuration, chart follow-ups use the deterministic intent-aware interpreter unless `VITE_ENABLE_LLM_INTERPRETATION=true` explicitly requests structured LLM synthesis. The interpreter now produces a `meaning_brief` that explains what the observed pattern means, why it matters, how to read it, what evidence should be checked next, and what the next grounded learning goal should be. User interactions that reveal weak but technically correct answers are converted into reusable rubric rules; for example, cohort-average answers must now explain that the average is a group summary, can hide divergent wells, and should be used as a screening entry point rather than a forecast. When optional synthesis is enabled and available, the local LLM is Ollama running a Qwen variant (`qwen3:8b` by default; configurable via `GROUNDWATERGPT_LLM_MODEL`), with optional hosted Qwen via DashScope when `DASHSCOPE_API_KEY` is set; benchmarks disable free-form LLM narration. The local-Ollama path is sensitive to first-call latency: on cold start the framing step alone can exhaust the per-request synthesis budget, in which case the deterministic pipeline still returns a complete answer. This is a reliability property, not a quality property. Numeric trend values flow from deterministic analysis into AI prompts; they do not originate from the model.

**What is evaluated (no LLM active).** The 68-case chat benchmark and the 25-case interpretation benchmark both run with the LLM disabled. The chat benchmark validates that the deterministic pipeline returns complete reports, citations, charts, and provenance. The interpretation benchmark validates that the intent-aware chart interpreter answers shallow-vs-deep, fastest-changing, cohort-meaning, and risk questions correctly from deterministic metrics, while unit tests now check that "what does this mean?" produces a significance-oriented explanation rather than data-only restatement. Each interpretation case is scored against 20 checks including grounding status, data references, expected terms and site IDs, numeric match within tolerance, guardrail compliance, and contextual rather than generic responses. The latest deterministic chat benchmark scored 1.000, while the latest interpretation benchmark scored 0.943 and passed thresholds with 1.000 grounding, numeric-match, and guardrail coverage. A separate evidence-guided synthesis benchmark now checks that grounded chat and interpretation replies expose `next_goal` plus grouped follow-up questions without inventing measurements.

**What is architecturally present but not the evaluated core.** An in-process Ollama narration path produces short hydrogeologist summaries when the LLM is enabled; narration is disabled in benchmarks (`GROUNDWATERGPT_DISABLE_LLM_SYNTHESIS=1`). A separate `DeepResearchAgent` for open-ended questions was quarantined to `legacy/` in 2026-04-29 because it was disabled in every active path (demo, tests, both benchmarks) and was not part of the evaluated system; it remains in version control for reference but is excluded from the test suite and pre-commit. A one-case chart-explainability LLM smoke passed with 44.8 s elapsed — an architectural check on the live narration path, not a quality evaluation.

**What the current LLM does.** The default local LLM for optional synthesis is Ollama Qwen (`qwen3:8b` unless `GROUNDWATERGPT_LLM_MODEL` or a route-specific override is set), used only for narration or structured chart synthesis over deterministic context when enabled and available. If `DASHSCOPE_API_KEY` is present and the frontend requests chart LLM synthesis, the chart interpreter can try hosted Qwen first using `GROUNDWATERGPT_INTERPRETER_MODEL` (default `qwen-plus`) and requires a structured `InterpretationResult`. Successful chart synthesis reports the provider/model in the response grounding fields. Any numeric claims are reconciled against deterministic EvidencePack values before emission. If hosted Qwen or Ollama is unavailable, the deterministic intent-aware interpreter still returns the answer.

**What the LLM layer is designed to do.** The claim/evidence contract restricts factual output to registered deterministic claims and evidence IDs. The sponsor-facing RAG path uses a curated hydro interpretation bank for concepts such as drawdown, recharge, seasonal variability, aquifer confinement, supply-proxy limits, and saltwater-intrusion caveats. When active, the LLM/RAG layer can explain what an observed pattern may mean and what evidence would confirm it, while quantitative conclusions remain grounded in USGS records. This separation is the intended architectural contribution, but it is evaluated only through the deterministic benchmarks and mock-LLM unit tests — not through a multi-case LLM benchmark.

### 3.5 Limitations

The system has several explicit limitations. First, the validated scope is Florida-specific and repository-bounded. The site catalogue contains 44 metadata entries across five Florida counties and 40 canonical local time-series files; adding sites currently requires metadata and data-file updates rather than dynamic national USGS discovery. Second, the trend estimator is OLS on monthly means. It does not remove seasonality, correct serial correlation, report confidence intervals, or use robust non-parametric estimators. Third, changepoints, divergent pairs, behavior clusters, and risk labels are deterministic screening tools, not peer-reviewed hydrologic inference methods. Fourth, the current analysis does not include precipitation, pumping, land-use, salinity, chloride, canal-stage, or other external covariates, so the system can interpret observed monitoring patterns but cannot prove causation. Fifth, monitoring wells are proxies and may not perfectly represent water-supply production wells unless construction, screened interval, location, and utility documentation align. Sixth, an open-ended `DeepResearchAgent` exists in `legacy/` but is not part of the evaluated system; it was disabled in the demo, all tests, and both benchmarks, and quarantined out of the live tree because its quality has never been validated. Seventh, LLM wording is stochastic even though deterministic data, chart, citation, and provenance fields are reproducible; the bounded evidence-guided synthesis contract is benchmarked, but no stable multi-case benchmark exists yet for broad free-form narration or autonomous agent behavior. Eighth, the intent classifier uses regex matching, which correctly handles the tested question phrasings but may misclassify novel wording; extending it to a lightweight learned classifier would improve robustness. Finally, the knowledge base is intentionally narrow and should not be described as comprehensive groundwater literature coverage.

## Data Availability

The groundwater observations used by EAGLE are public USGS National Water Information System records cached locally as canonical `data/usgs_<15-digit-site-id>.csv` files. The repository metadata catalogue contains 44 monitoring-well entries, and the manuscript-facing data archive contains 40 canonical time-series CSVs spanning 1994-01-01 through 2026-04-05 across the shipped dataset. The local knowledge base is a ChromaDB store built from hydrogeology reference PDFs, generated per-well summaries, a small domain Q&A corpus, and a curated hydro interpretation bank used by the chart-follow-up interpreter. Reproducibility anchors are provided by the committed benchmark case definitions in `tests/benchmark/` (68 chat cases and 25 interpretation cases), regenerable benchmark reports emitted by the benchmark scripts (`chat_benchmark_report.json`, `interpretation_benchmark_report.json`), and response-level `research_provenance_v1` hashes emitted by the API.

## Reproducibility Appendix

1. Clone and install the repository: `git clone https://github.com/walatheo/GroundwaterGPT.git`, `cd GroundwaterGPT`, create a Python environment, and install dependencies from `requirements.txt`.
2. Start the deterministic demo with `make demo`; this launches FastAPI and the Vite frontend with `GROUNDWATERGPT_SKIP_AGENT_INIT=1`.
3. Run the deterministic benchmark with `python3 scripts/run_chat_benchmark.py --mode fallback --enforce-thresholds` or `make benchmark`. Expected closeout result: 68 cases, overall score 1.000, average citation coverage 1.000, median latency under 2 s, and threshold pass `True`.
4. Run the interpretation benchmark with `python3 scripts/run_interpretation_benchmark.py --disable-llm --enforce-thresholds`. Expected closeout result: 25 interpretation cases, overall score around 0.943, grounding coverage 1.000, numeric match rate 1.000, guardrail pass rate 1.000, and threshold pass `True`.
5. Inspect `chat_benchmark_report.json`, `interpretation_benchmark_report.json`, and each API response's `research_provenance_v1` block to verify source files, method flags, and response hashes.

## 4. Conclusions

EAGLE demonstrates a practical architecture for making public groundwater monitoring records more usable while preserving auditability. Its contribution is the coupling of a deterministic Florida USGS data pipeline with structured claim/evidence binding, cross-well and cross-aquifer cohort presentation, chart/map generation, citation-integrity checks, provenance hashing, and an intent-aware interpretation layer that answers common chart questions — shallow-vs-deep comparison, fastest-changing well, cohort meaning, risk explanation — directly from deterministic metrics before any language model is invoked. The deterministic layer passed a 68-case benchmark with complete citation and claim-verdict coverage, and the chart interpretation layer passed a separate 25-case benchmark with 0.943 overall score plus 100% grounding coverage, numeric match rate, and guardrail compliance. Together, these results show that informative, chart-backed groundwater answers can be produced without depending on a language model for quantitative conclusions.

The system should not be framed as a replacement for hydrogeologic modeling or formal trend analysis. Its current role is a reproducible exploratory and communication layer for monitored groundwater records. Future work should expand dynamic USGS site ingestion, add Mann-Kendall and Sen's slope or other robust estimators, quantify uncertainty, validate risk labels with expert review, extend the regex-based intent classifier toward a lightweight learned model for broader question coverage, and benchmark the LLM synthesis layer separately from the deterministic reference pipeline. With those extensions, the same architecture could support broader auditable environmental-data interfaces while keeping the core scientific claims tied to measured records.
