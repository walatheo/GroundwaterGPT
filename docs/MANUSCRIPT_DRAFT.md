# EAGLE: Evidence-Aligned Groundwater Level Explorer for Auditable Florida USGS Groundwater Trend Analysis

**Draft status.** This manuscript draft reflects the repository closeout state on 2026-04-15. The user-facing system name is EAGLE (Evidence-Aligned Groundwater Level Explorer); repository paths and environment variables may still contain the historical `GroundwaterGPT` name for compatibility.

## 1. Introduction

Public environmental monitoring programs have created large scientific datasets whose practical value is limited by the gap between available records and usable research outputs. The U.S. Geological Survey (USGS) National Water Information System is a central example for groundwater science: it exposes long-running well records, but answering a local research question still requires site discovery, data cleaning, time-series aggregation, hydrogeologic context, visualization, and careful citation of the source records. Recent language-model systems make scientific data easier to query, but many rely on retrieved text as the primary evidence layer. For hydrologic applications, that is not enough. A useful system must keep quantitative claims tied to measured records, make charts reproducible, and expose the data and method path behind each answer.

This study presents EAGLE, an auditable research interface for Florida groundwater monitoring records. The central contribution is not the use of a language model by itself. The novelty is a deterministic USGS data pipeline that transforms local Florida well records into claim-bound, chart-backed, cross-cohort groundwater summaries, then exposes those summaries to a language model only through structured claim and evidence identifiers. In this design, the language model functions as a narration and synthesis layer. Numeric conclusions, trend directions, cohort comparisons, source links, chart payloads, citation-integrity metrics, and provenance hashes are produced by deterministic code before any free-form explanation is emitted.

The manuscript focuses on a bounded Florida monitoring network rather than a national deployment. The repository currently contains 44 site metadata entries and 40 canonical local USGS time-series CSVs, with daily depth-to-water observations spanning 1994-01-01 through 2026-04-05 across the shipped dataset. EAGLE uses these records to answer descriptive trend and aquifer-context questions, including site-specific change, nearest-well location summaries, cross-well cohort behavior, cross-aquifer comparisons, divergent-well screening, map context, and reproducible time-series chart generation. The objectives are to describe the architecture, evaluate whether the deterministic layer returns citation-complete and reproducible answers, and identify the statistical limitations that must be addressed before the system can support stronger hydrogeologic inference.

## 2. Methods

EAGLE is implemented as a FastAPI backend with a React frontend. The backend prioritizes deterministic analysis before any language-model synthesis. A routing chain detects explicit well IDs or names, aquifer names, Florida locations, multi-location comparisons, and network-wide questions. Location queries use a reproducible nearest-neighbor proxy-selection rule based on Haversine distance with a county-match bonus. This rule is a site-selection heuristic rather than a spatial interpolator.

The data layer operates on canonical USGS CSV files named `usgs_<site_id>.csv`, each containing `site_no`, `datetime`, and `value`, where `value` is depth to water in feet below land surface. The loader coerces timestamps and numeric values, drops invalid rows, sorts chronologically, and caches the resulting per-site dataframe. Downstream analysis resamples daily values to month-start means. For each well, the deterministic pipeline computes record start and end dates, net change, ordinary least-squares annualized rate of change on monthly means, and a qualitative trend class.

The cohort layer is where much of the manuscript novelty sits. For a selected set of wells, the system computes a cross-well trend distribution, mean annual change, standard deviation of annual change, top divergent pairs, candidate changepoints, deterministic behavior clusters, and a cohort risk label. Divergent pairs identify wells with the most contrasting annual rates and are used as screening signals for local heterogeneity or possible measurement/context differences. Candidate changepoints are detected by comparing a single OLS fit with a two-segment OLS fit and requiring at least a 20% residual-error improvement. Behavior clusters are built from standardized local-data features, including annual change, seasonal amplitude, and confinement indicator. These cohort tools are reproducible screening heuristics, not formal proofs of aquifer connectivity, causality, or regime shift.

For presentation, the same deterministic object is rendered into both human-readable text and machine-readable audit fields. Each report includes `claim_citations`, claim verdicts, citation summary, section confidence, citation-integrity status, and a `structured_response` using the `evidence_response_v1` schema. Every factual claim must bind to registered claim IDs and evidence IDs. If a language model is used, it must return structured JSON whose claims intersect with the pre-approved deterministic registry; claims without valid IDs are dropped. This claim/evidence binding is the core guardrail that prevents the language model from becoming the source of quantitative groundwater conclusions.

The chart pathway is similarly constrained. Time-series chart payloads are produced as Recharts-ready JSON by a single chart builder used by deterministic and agentic paths. Charts include monthly well series, a cohort-average series when applicable, trend overlays with annualized rates, highlighted divergent wells, and chart insight bullets. Because the measured variable is depth to water below land surface, the frontend inverts the y-axis so deeper water levels plot downward. Map context is generated from the same site metadata used by the router, allowing users to inspect the spatial distribution of the selected Florida wells without leaving the application.

Reproducibility is tracked through a `research_provenance_v1` block. Each response records a code commit when available, a SHA-256 hash of the response, hashes of the data snapshot and configuration files, and method flags describing the trend, changepoint, cluster, citation, and external-covariate settings. This means a reviewer can inspect not only a natural-language answer but also the data files, chart payload, claims, citations, and method path behind it.

## 3. Results and Discussion

### 3.1 Deterministic Benchmark Performance

The manuscript-facing benchmark contains 68 groundwater questions across routing modes including generic fallback, site fallback, aquifer fallback, and network fallback. In deterministic fallback mode, with the language-model agent disabled, EAGLE passed 68 of 68 cases. The current benchmark report produced an overall score of 1.000, average citation coverage of 1.000, average claim-citation coverage of 1.000, average section-citation coverage of 1.000, and average claim-verdict coverage of 1.000. Median response latency was 4.173 s and maximum latency was 8.070 s on the latest clean local run. These latency values were measured with the FastAPI in-process `TestClient`; deployed client-server latency will be higher and should be benchmarked separately.

These results should be interpreted as a software and auditability evaluation, not as proof that the hydrologic trend labels are scientifically optimal. The benchmark verifies that the system returns expected fields, cites claims, reports dates and trend metrics, emits structured evidence, and satisfies response-time thresholds. It does not validate risk-label calibration, groundwater causality, seasonality-corrected trends, or external generalization.

### 3.2 USGS Data Presentation and Cross-Cohort Analysis

The strongest result is the integration of raw USGS well records into a usable research presentation layer. A user can ask about a Florida location or aquifer and receive a cohort summary that includes the wells selected, their aquifer labels, period of record, net changes, annualized rates, cross-well trend distribution, highlighted divergent pairs, candidate changepoints, behavior clusters, and source URLs. This turns a collection of individual site records into an auditable cross-cohort view that can support exploratory groundwater research and manuscript drafting.

The cross-cohort design is important because single-well trends can be misleading when interpreted without nearby wells, aquifer context, or record-length visibility. EAGLE does not claim that a divergent pair proves a hydrologic mechanism. Instead, it makes divergence visible, ties the observation to specific site records, and encourages follow-up review. That is an appropriate role for an auditable screening interface.

### 3.3 Chart and Map Outputs

The chart layer makes the deterministic analysis inspectable. Time-series payloads expose monthly depth-to-water values, cohort-average behavior, highlighted wells, and trend overlays using the same annual rates reported in the text and claim registry. A cross-path parity test ensures that deterministic, agent-attached, and streaming paths share the same chart schema. This avoids a common failure mode in AI-assisted analysis systems where text and visuals are generated by separate logic and can drift apart.

Map outputs provide geographic context for the monitored wells and for location-based cohort selection. The current nearest-neighbor method is intentionally simple and reproducible. It should be described as a proxy-selection method for monitored wells near a user-referenced place, not as interpolation, regional modeling, or a complete spatial analysis of Florida groundwater.

### 3.4 Language-Model Role

The language model is useful for summarizing deterministic outputs, organizing findings, and answering broader research-style questions, but it is not the source of measured groundwater facts. EAGLE's claim/evidence contract restricts factual output to registered deterministic claims and evidence IDs. This separation makes the system more manuscript-safe than a conventional retrieval-augmented chatbot: the LLM can improve readability, but the quantitative answer remains grounded in USGS records and reproducible code.

The current evaluation primarily validates the deterministic layer. A bounded live-agent smoke benchmark was also run through `scripts/run_agent_benchmark.py` using local Ollama `llama3.2` and the first shared benchmark case. That run confirms that the live `DeepResearchAgent` path can route through `deep_research` and emit the typed audit envelope: agent-routed rate was 1.000, structured-response coverage was 1.000, and provenance coverage was 1.000. However, the smoke result should not be interpreted as a stable LLM quality benchmark: it covered 1/68 cases, scored 0.200 overall, had 0.000 citation and claim-verdict coverage in the latest run, failed the live threshold policy, and took 270.155 s. A narrower chart-explainability LLM smoke benchmark now validates the sponsor-facing use case more directly: local Ollama narration over deterministic chart context passed its one-case smoke with 1.000 LLM-synthesis coverage, 1.000 chart-explainability coverage, and 44.816 s elapsed. Together, these results support the architectural claim that language models can communicate with the data product, while showing that the full research-agent path still needs tuning before being used as manuscript evidence.

### 3.5 Limitations

The system has several explicit limitations. First, the validated scope is Florida-specific and repository-bounded. The site catalogue contains 44 metadata entries across five Florida counties and 40 canonical local time-series files; adding sites currently requires metadata and data-file updates rather than dynamic national USGS discovery. Second, the trend estimator is OLS on monthly means. It does not remove seasonality, correct serial correlation, report confidence intervals, or use robust non-parametric estimators. Third, changepoints, divergent pairs, behavior clusters, and risk labels are deterministic screening tools, not peer-reviewed hydrologic inference methods. Fourth, the current analysis does not include precipitation, pumping, land-use, or other external covariates, so the system reports observed monitoring-record patterns rather than causal attribution. Fifth, LLM wording is stochastic even though deterministic data, chart, citation, and provenance fields are reproducible; the local live-agent smoke uses `llama3.2` and is not yet a stable full-suite benchmark. Finally, the knowledge base is intentionally narrow and should not be described as comprehensive groundwater literature coverage.

## Data Availability

The groundwater observations used by EAGLE are public USGS National Water Information System records cached locally as canonical `data/usgs_<15-digit-site-id>.csv` files. The repository metadata catalogue contains 44 monitoring-well entries, and the manuscript-facing data archive contains 40 canonical time-series CSVs spanning 1994-01-01 through 2026-04-05 across the shipped dataset. The local knowledge base is a ChromaDB store built from hydrogeology reference PDFs, generated per-well summaries, and a small domain Q&A corpus. Reproducibility anchors are provided by the committed benchmark case definitions in `tests/benchmark/`, the deterministic benchmark report `chat_benchmark_report.json`, the bounded live-agent smoke report `agent_benchmark_report.json`, and response-level `research_provenance_v1` hashes emitted by the API.

## Reproducibility Appendix

1. Clone and install the repository: `git clone https://github.com/walatheo/GroundwaterGPT.git`, `cd GroundwaterGPT`, create a Python environment, and install dependencies from `requirements.txt`.
2. Start the deterministic demo with `make demo`; this launches FastAPI and the Vite frontend with `GROUNDWATERGPT_SKIP_AGENT_INIT=1`.
3. Run the deterministic benchmark with `python3 scripts/run_chat_benchmark.py --mode fallback --enforce-thresholds` or `make benchmark`. Expected closeout result: 68 cases, overall score 1.000, average citation coverage 1.000, and threshold pass `True`.
4. Run the bounded live-agent smoke with `python3 scripts/run_agent_benchmark.py --limit 1 --output agent_benchmark_report.json --provider ollama --model llama3.2`. Expected closeout result: one `deep_research` case with structured-response and provenance coverage present, but live thresholds not yet passing because latency and content coverage remain unstable.
5. Inspect `chat_benchmark_report.json`, `agent_benchmark_report.json`, and each API response's `research_provenance_v1` block to verify source files, method flags, and response hashes.

## 4. Conclusions

EAGLE demonstrates a practical architecture for making public groundwater monitoring records more usable while preserving auditability. Its contribution is the coupling of a deterministic Florida USGS data pipeline with structured claim/evidence binding, cross-well and cross-aquifer cohort presentation, chart/map generation, citation-integrity checks, and provenance hashing. The deterministic layer passed a 68-case benchmark with complete citation and claim-verdict coverage, showing that informative, chart-backed groundwater answers can be produced without depending on a language model for quantitative conclusions.

The system should not be framed as a replacement for hydrogeologic modeling or formal trend analysis. Its current role is a reproducible exploratory and communication layer for monitored groundwater records. Future work should expand dynamic USGS site ingestion, add Mann-Kendall and Sen's slope or other robust estimators, quantify uncertainty, validate risk labels with expert review, and benchmark the LLM synthesis path separately from the deterministic reference pipeline. With those extensions, the same architecture could support broader auditable environmental-data interfaces while keeping the core scientific claims tied to measured records.
